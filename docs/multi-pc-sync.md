# 自宅PCとラボPCで進捗を共有する

要約版管理に対応したPaperFlowではDB version 4・共有データversion 2を使う。両PCを同じ版へ更新する。旧データは読み込めるが、新しい共有データを古いアプリで開くことはできない。[再要約・履歴の同期](summary-versions.md#pc間同期)

## 最初のPCで設定する

1. PaperFlowを再起動し、**PC間同期** タブを開く。
2. Paperpileフォルダ・BibTeXファイル・Obsidian Vaultを選び、**このPCのパスを保存** を押す。
3. **Drive内の専用共有フォルダ** に、空のフォルダを指定する。例：`H:\My Drive\PaperFlow-Sync`。
4. Windows右下のGoogle Driveアイコンを開き、同期が完了していることを確認する。
5. **最初のPC：共有を新規作成** を押し、表示された保存先を確認して作成を承認する。初回は手順3のチェック操作は不要。
6. **共有データを作成しました** と表示され、フォルダ内に `paperflow-workspace.json`・`commits`・`objects` ができたことを確認する。

このPCの文献DB・保存済み要約・消費量・対象一覧と実行状況が、専用フォルダへ保存される。Google Driveデスクトップ版がそのファイルを同期する。Google Cloud登録・API有効化・OAuthクライアント・PaperFlowへのGoogleログインは不要。

共有フォルダはPaperpile・Vault・C:の作業フォルダとは分離する。稼働中のSQLite・PDF・CLI認証情報はここへコピーしない。各PCのGoogle Driveデスクトップ版には同じGoogleアカウントでログインする。

## もう一方のPCで設定する

1. 同じ版のPaperFlow・Windows用Python・使用するCLIを用意する。
2. Google DriveでPaperpile・Vault・専用共有フォルダの同期が完了するまで待つ。
3. PaperFlowの **PC間同期** で、このPCのPaperpile・BibTeX・Vaultのパスを保存する。
4. 最初のPCで作った専用共有フォルダを選ぶ。ドライブ文字はPCごとに異なってよい。
5. 前PCの送信とこのPCの受信が完了していることをDriveで確認し、チェックを入れる。
6. **2台目：既存の共有を引き継ぐ** を押す。
7. 必要なら **共有解析設定を適用** を押す。PDF送信・Vault保存の許可は、このPCでも設定する。
8. CLI認証が必要なら **Claudeにログイン** / **Codexにログイン** を押す。

2台目で共有フォルダを新規作成しない。識別ファイルやセーブ本体がまだ届いていない場合は、Driveの同期を待つ。

すでにこのPC独自のDBがある場合は **空の作業DBへ切替** を押してから参加する。元のDBと解析結果は元の場所に残る。別々に作った文献DBは自動合併しない。原本フォルダの内部配置とPDF内容は両PCで同じものを使う。

## 普段の使い方

1. 前PCで **共有フォルダへ保存して終了** を押す。処理中なら現在の1本が終わるまで待つ。
2. **終了後、前PCのGoogle Driveが同期完了になるまで待つ。** PCを先にシャットダウンしない。
3. 次のPCでもGoogle Driveの同期完了を待ち、PaperFlowを起動する。
4. 起動時に、見えている共有ファイルを受信する。この段階では閲覧のみ。
5. **PC間同期** で **Driveの同期完了を確認しました** にチェックし、**確認して取り込みを許可** を押す。
6. **履歴・消費量** から前回の対象一覧を開き、残りを実行する。

**共有フォルダ保存済みは、クラウド送信完了を意味しない。** PaperFlowはDriveのクラウド上の最新版や転送完了を自動判定しない。PC切り替え時は両端末のDriveで確認する。ネットワーク切断・Drive停止などで完了を確認できないときは、確認ボタンを押さず閲覧だけにする。

確認は起動ごとに必要。初回は作成ダイアログでDrive完了と保存先を確認する。次回起動・PC切り替え時はチェックと確認ボタンを操作する。確認後は、その起動中に論文ごとの共有フォルダ保存を行う。途中で確認を取り消す場合はチェックを外す。

未取り込みを全件、追加N本、累計N本、新着追加は従来どおり。[通常の使い方](usage.md)

## AIとモデルを共有する

「取り込み」でProvider・モデルを選び、**設定を保存**。「PC間同期」で **現在の解析設定を共有** を押す。別PCでは共有ファイルを受信後、**共有解析設定を適用** を押す。

同期中の実解析はモデルIDを明示選択する。研究文脈・taxonomy・読解設定も共有する。PCごとのパス・CLI実行ファイル・送信/保存の許可は個別設定を保持する。保存済み解析と入力・設定が一致する場合、AIを呼び直さず再利用する。

## 止まったとき

| 状態 | 操作 |
|---|---|
| この起動では引き継ぎ未確認 | Driveの同期完了を確認し、チェックと確認ボタンを操作する |
| 共有セーブや本体の同期待ち | Driveの受信完了を待ち、**共有ファイルを受信・更新** を押す |
| 前回確認した世代が見えない | 正しいフォルダか確認し、Driveの受信を待つ。古い進捗へ自動で戻さない |
| 共有フォルダへ未保存 | このPCのC:に結果がある。共有先のアクセスを直し、確認後に受信・更新する |
| 前PCの処理終了待ち | 前PCのPaperFlowとCLIが終了し、Drive同期が完了したことを確認して **前PCの終了を確認して引き継ぐ** |
| 解析結果が未確認 | 前回の保存済み回答を確認する。再送してよい場合だけ **結果未確認の再送停止を解除** |
| Vaultのファイル同期待ち | 表示されたフルパスのファイル到着を確認する。旧「マイドライブ」の保存履歴は現在の「My Drive」へ読み替える。取り込み済みを未処理へ戻して再解析しない |
| 解析設定が違う | **共有解析設定を適用**、または変更を保存して **現在の解析設定を共有** |
| 進捗が分岐 / 競合コピー / 未保存変更と別PC更新が両方ある | 両PCで処理を止め、C:のDB・バックアップ・共有ファイルを比較する。自動で片方を上書きしない |
| 旧版の解析設定が未確認 | 成功結果は保持される。元PCで固定入力と解析設定を確認する。自動再送しない |

書き込み失敗で画面を閉じてもC:の結果は残る。このPCから共有フォルダへ保存し、Driveの同期完了を確認するまで別PCで続行しない。

## 新しいPCへのアプリ導入

1. Gitで取得したソース一式をこのPCのC:へ置く。`.data`・`.venv-win`・`.tools`・既存ショートカット・個人設定はコピーしない。
2. **setup.cmd** をダブルクリックする。Python・依存ライブラリ・安全な初期設定・起動アイコンが用意される。
3. 使用するWindows用CLIを導入し、開いたGUIで保存先・CLIパス・ログイン・共有フォルダを設定する。

既存の個人設定は再実行しても上書きしない。[セットアップの詳細](setup.md)

## 保存ファイルと復旧

共有フォルダの構造：

```text
PaperFlow-Sync/
  paperflow-workspace.json       共有ライブラリのID
  commits/<セーブID>.json        親セーブ・端末・データのハッシュ
  objects/<SHA256>.json.gz       論理DB・解析JSON・固定バッチ
```

- DB本体は各PCのC:。同期するのは論理データで、絶対パス・PDF・全ページ画像・ロック・認証情報を除く。
- 原本とVaultは既存のDrive同期を使う。共有フォルダとVaultの到着順は一致しないため、必要なファイルがない場合は待つ。
- 本体の保存後にコミットを公開する。Driveが逆順に届けた場合も、親・本体・ハッシュが揃うまで取り込まない。
- ファイルは上書きしない。セーブIDの親子関係で分岐を検出し、同じデータ本体はハッシュで再利用する。
- 解析開始前、検証済み解析の保存後、Vault反映前後、処理終了時に共有フォルダへ保存する。
- 回答の保存を確認できない解析は、同じPCでの強制終了を含め、自動再送しない。
- 受信前のDB・対象一覧はC:の `progress-sync/backups/` に退避する。受信途中の障害はローカルの受信journalから復旧する。
- 同期設定はC:の `progress-sync/settings.json`。GUIで操作し、通常は編集不要。
- 1セーブは圧縮32MiB・展開128MiBまで。世代履歴は自動削除しない。2万セーブで履歴整理を求めて停止する。
- 同時利用を保証する分散ロックではない。同時利用しない。利用者が確認しても、まだ届いていない未知の新世代は検出できない。古い端末コピーを最新と誤認しないよう、Driveの完了を確認する。

共有フォルダはDrive側で「オフラインで使用可能」にしておくと受信時のファイル取得待ちを減らせる。共有ファイルを手動で改名・編集・一部削除しない。

## 旧API設定がある場合

旧API方式は実行できず、GoogleへのAPI通信も行わない。**このPCの同期を解除** してから、新しい空の共有フォルダを作成する。元のC:の文献DB・解析結果は保持される。旧APIの未保存セーブがある場合は、元のC:データを退避してから移行する。

以前にGoogle認可を行った場合、不要な認可はGoogleアカウントの接続済みアプリから利用者が解除できる。PaperFlowはGoogle認証情報の読み取り・移送・自動削除を行わない。

## 検証範囲

合成PDF・一時Vault・2端末のフォルダ配送を使い、異なるパス間の解析再利用、固定バッチの往復再開、同期待ち、破損、古いコピー、分岐、途中終了、確認前の書き込み禁止を検証する。GUIもGoogle APIへの通信を禁止した状態で試験する。

実際の自宅PCとラボPCを使ったDrive配送は未検証。最初の共有先選択と実データ共有は、GUIで利用者が開始する。
