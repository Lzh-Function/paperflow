# 現在のPaperpileに合わせた入力上限

2026-11-17に、G:のPaperpileにある全341ファイル（同一内容の重複を除く338 PDF）を読み取り、全8,140ページをローカルで画像化して計測した。

| 設定 | 実測最大 | 旧値 | 変更後 |
|---|---|---|---|
| `visual_max_pages` | 264ページ | 60 | **300** |
| `visual_max_pdf_mb` | 44.35MiB | 20 | **64** |
| `visual_max_image_mb` | 91.28MiB | 40 | **128** |
| `max_chars` | 2,785,460文字 | 80,000 | **3,000,000** |

変更後は、確認した全341ファイルがこの4項目の上限内になる。最大値ぴったりではなく、少し余裕のある区切りへ切り上げた**PaperFlow側の運用値**。モデルやCLIの入力可能量を意味する値ではない。

`config.production.yaml`、`config.yaml`、`config.example.yaml`と、項目省略時の既定値をそろえた。変更の妨げになっていた、以前の設定バリデータの100ページ・24MiB・100万文字等の固定天井も取り除いた。設定値は正の整数、文字数は100以上を指定する。

元の値では、60ページ超が12ファイル、PDF20MiB超が15ファイル、補助本文8万文字超が203ファイルあった。全PDFのPNGまで調べると、PNG40MiB超は4ファイルだった（いずれも旧ページ/PDF上限で既に対象外だったもの）。複数項目に引っ掛かるPDFがあるため、件数は単純加算しない。旧設定でページ・容量により止まるものは計23ファイル。

## 待ち時間と費用について

`timeout_seconds: 240`、`max_retries: 3`、`retry_base_seconds: 30`、`max_cli_calls_per_run: 10`、Claudeの`max_budget_usd: 0.5`は今回変更していない。PDFの大きさだけでは適正な待ち時間・試行回数・費用を測れないためであり、これらが実測済みの推奨値になったわけではない。

実際のAI解析で時間やCLI表示費用の上限に達する場合は、対象を選んで試した結果を見て調整する。今回の計測で実PDFを外部LLMへ送信していない。送信・Vault書き込み許可のスイッチも変更していない。

## モデル側の制限は別

Claudeの公式PDF仕様は、リクエスト全体が最大128MB、PDFは最大600ページで、コンテキストが1M未満の場合は100ページまでという条件がある。100ページを超えるPDFには対応するモデル・コンテキストを選ぶ。これはClaude APIの公表条件であり、Claude Code CLIの入力制限とは異なる。CLI向けには作業PDFの合計16MiB以内への調整と100ページ単位の分割を別途行う。G:原本やVaultの凍結PDFは変更しない。詳細は [視覚入力の準備](visual-reading.md#大容量pdfのclaude入力準備)。[Claude PDF仕様](https://platform.claude.com/docs/en/build-with-claude/pdf-support)

OpenAIの画像入力には、リクエスト容量・画像枚数のほか、モデルのコンテキストや画像処理の制限がある。PaperFlow側の128MiBを通過しても、選択したCodexモデルで解析できる保証にはならない。[OpenAI画像入力仕様](https://developers.openai.com/api/docs/guides/images-vision)

ページを勝手に間引く・文字だけへ切り替える動作は行わない。モデル側で受け付けられなければ失敗として報告する。

## 画像化の後始末

今回の容量計測は、1ページずつメモリ上でPNGを作り、サイズを足した後に破棄した。**計測用画像のディスク保存は0件**。計測ワーカーも終了済み。残すのは計測値のJSON・レポート等だけ。

実際の要約処理でCodex用に作る全ページPNGと入力PDFの作業コピーは、一時ディレクトリに隔離し、成功時・例外時・タイムアウト時に削除する。Obsidianへ添える選択済み図表は成果物なので保存する。OSによる強制終了や停電は通常の終了処理が動かないため、同じ削除保証の対象ではない。

計測の詳細は `.data/pdf-limits-audit/2026-11-17-185603/REPORT.md` と `full-result.json`。PDF内部構文の警告も記録しており、容量が上限内であることとPDFの内容・読解の正確さは別に扱う。
