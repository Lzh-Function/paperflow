# PaperFlow 操作マニュアル

初めてのPCでは、C:に置いたフォルダ内の **setup.cmd** をダブルクリックする。[初回セットアップ](setup.md)

## 1. PaperFlowを開く

デスクトップの **PaperFlow** アイコンをダブルクリックする。

プロジェクトフォルダにも同じ起動アイコンがある。

```text
C:\Users\TAKUH\Documents\paperflow\PaperFlow.lnk
```

「取り込み」「論文一覧」「履歴・消費量」「復旧・後処理」「設定」「PC間同期」の6つのタブが開く。起動しただけでは論文の送信は始まらない。

### 失敗・未保存をまとめて処理する

1. **復旧・後処理** タブを開く。失敗した論文と、要約があるのに保存できていない論文が一覧に出る。
2. まず **保存するだけ**、**保存済み回答の再検証候補**、**別保存の成功結果候補** を選ぶ。Ctrl/Shiftで複数選択できる。
3. **再送せず復旧・保存** を押し、対象を確認して実行する。保存済みの回答を検証し、通過した論文をObsidianへ保存する。AIへは送信しない。
4. 回答が残っていない論文は **再解析が必要** で絞り込む。**取り込み** タブでAI・モデルを選んでから戻り、対象を選んで **選択分を再解析・保存** を押す。PDF送信先と対象の確認に承認すると解析・保存が始まる。
5. **結果を表示** で1本ごとの成功・失敗理由と追加CLI解析試行数を確認する。停止・失敗分は **前回の後処理** から選び、**選んだ作業を再開** する。

**処理可能をすべて選択** は、表示中の一覧から確認が必要なもの・解決済みを除いて選ぶ。保存済み回答をC:で検査するだけなら **保存済み回答を再検証** を使う。登録済み論文の本文はこの画面から切り替えない。

PaperFlowの試験フォルダに成功結果がある場合は **別保存の成功結果を取り込む** でフォルダを指定できる。`manifest.json`・`analysis.json`・`result.json`・`input-audit.json`・`verification.json` の元PDF・モデル・成功記録と現在の入力を照合する。PaperFlow内の試験結果保存先にある候補は一覧へ自動表示し、**再送せず復旧・保存** でも取り込める。試験時のモデル・取得済み使用量を保持し、新たなAI利用として二重計上しない。

認証切れ・CLI未導入など共通の障害では後続を停止する。個別の検証・保存失敗は記録して次へ進む。前回の解析結果が未確認の場合は、先に **PC間同期** の確認操作を行う。失敗記録やC:のプレビューを自動削除せず、未登録の出典を取り込み済みとも記録しない。

復旧の作業一覧と結果はこのPCのC:に保存する。PC間同期を使う場合、論文の解析・保存の結果は従来どおり共有される。別PCでは **復旧・後処理** で残りを照合して選び直す。

### 論文一覧を見る

**論文一覧** タブを開くと、同期済みのPaperpile文献が並ぶ。

- 状態欄で **取り込み済み** と **未取り込み（失敗等も含む）** を切り替える。
- **未処理／要約済み・未保存／解析中／失敗・中断／要確認・PDF未検出** でも絞り込める。
- 検索欄へタイトルの一部、著者、年、DOIなどを入力する。列の見出しを押すと並び替わる。
- 論文を選ぶと、下部に書誌情報・失敗理由・保存された要約が表示される。
- **PDFを開く**、**要約ノートを開く** で対応するファイルを開ける。

取り込み済みは、Obsidianへの保存を確認した文献。要約の生成だけが終わった文献は **要約済み・未保存** と表示する。C:だけに保存した別試験の成功を、本番取り込み済みとは扱わない。

Obsidian内で登録済み論文をタグ・発行年・著者と一緒に見る場合は、`Ctrl+O` から **論文データベース** を開く。[データベースの使い方](paper-database.md)

| ボタン | 動作 |
|---|---|
| **表示を更新** | 現在記録されている処理状況を読み直す。実行中も使用できる |
| **Paperpileと同期** | Google Driveに同期されたBibTeX・PDFを読み、新着・更新・削除を一覧へ反映する。取り込み停止中に使用する |
| **保存状況を照合** | Vaultの既存Source Noteと凍結出典を読み直して取り込み済み判定を更新する |

最初に一覧を開いたときも、既存Vaultの登録状況を照合する。以降、一覧の表示中は約3秒ごとにDBの処理状況を更新する。Vault全体の検証やPDFの再解析は行わない。

PaperpileのBibTeX・PDFから同期したPaperFlowの文献DBを表示する。これらの一覧操作はAI解析を開始せず、原本やVaultノートも変更しない。

### 保存済みの不採用回答を再検証する

1. GUIを起動し直し、**論文一覧** で対象の失敗した論文を選ぶ。
2. **保存済み回答を再検証** を押して確認する。AIへの再送信とObsidianへの保存は行わない。
3. 検証を通ると **要約済み・未保存** になる。
4. **履歴・消費量** から以前の一覧を開き、同じProvider・モデル・解析設定で取り込みを再開する。検証済みの回答を使って保存する。

図表番号や単純な重複の形式補正を行う。JSONの書式エラーで失敗した回答も、元の回答文字列とPDF入力の証跡が保存されていれば再検証できる。明確なエスケープ不備だけを文字を保持して補正し、補正内容を未確認事項へ記録する。PDF・書誌・モデル・解析設定と保存済みの入力記録が一致しない回答、構造が曖昧なJSON、読解未完了、ページ不足、不正な参照は採用しない。取り込み済みのノートは切り替えない。

### 登録済みの論文を別モデルで再要約する

1. **論文一覧** で状態を **取り込み済み** にし、再要約する論文を選ぶ。Ctrl/Shiftで複数選択できる。
2. **選択論文を再要約・版を比較** を押す。
3. 開いた画面でClaude/Codex/Antigravity CLI（agy）とモデルを選ぶ。必要なら **モデル一覧を取得** を押すか、モデルIDを入力する。
4. **再要約を開始** を押し、対象論文・モデル・PDF送信の確認に承認する。
5. 完了後、要約版を選び、左右の本文を読む。**図表付きで比較を開く** でブラウザに本文と図表を並べる。
6. 採用する版を選び、**選択版を正式版にする** を押して、Obsidianへの切り替えを確認する。

再要約するのは選んだ論文だけ。候補の生成時点では、Obsidianの正式ノートは変わらない。モデル名・生成日時・取得できた消費量を版ごとに表示する。以前の本文・図表も残り、同じ画面から旧版を正式版に戻せる。

通常の **未取り込みを全件／追加する本数／累計の目標** は、モデルを変えても登録済み論文を除外する。再要約画面のモデル指定は、その再要約だけに適用する。

対象はPaperFlowが管理するSource Note。正式ノートや統合提案に手動編集がある場合、またはWiki統合済みの場合は、自動切り替えを停止する。[要約の版管理・復旧・PC間同期](summary-versions.md)

## 2. AIと保存先を設定する

「取り込み」タブで次の順に操作する。

1. AIを **Claude Code CLI** / **Codex CLI** / **Antigravity CLI（agy）** から選ぶ。
2. **モデル一覧を更新** を押し、モデル欄から選ぶ。モデルIDを直接入力することもできる。空欄ならCLIの既定モデルを使う。
3. 入力フォルダと保存先が表示されているので確認する。
4. **PDFを外部送信して解析する** と **Obsidianへ保存する** にチェックを入れる。
5. **設定を保存** を押す。

これで選んだAI・モデルと、送信・保存の許可が保存される。保存時点では論文の解析は始まらない。

フォルダを変える場合は「設定」タブの「入力元」と「Obsidian」でパスを編集し、**設定を保存** を押す。その他の項目にも説明が表示される。設定は `config.production.yaml` に保存され、既存のコメントも保持される。

ログインは「PC間同期」タブの各CLIログインボタンから行う。agyは **agyにログイン** を使う。[agyの設定とPDF読解](agy.md)

Claude・Codexについては、未ログイン・期限切れのエラーが出た場合は、PowerShellで該当するコマンドを実行する。

```powershell
claude auth login
```

```powershell
codex login
```

## 3. 全件か、本数指定かを選ぶ

「取り込み」タブで、次のいずれかを選ぶ。

| 選択肢 | 動作 |
|---|---|
| **未取り込みを全件** | 処理可能な未取り込み論文をすべて選ぶ。本数の入力は不要 |
| **追加する本数** | 本数欄へ入力した数だけ、未取り込みから乱択する |
| **累計の目標** | 本数欄へ入力した累計に達するまでの不足分を乱択する |

すでにObsidianへ登録した論文は除外する。候補が足りない場合は、不足する本数を表示する。

選んだら **対象一覧を作成** を押す。書誌とPDFが照合され、論文名・年・ページ数が画面に並ぶ。この段階では外部AIへ送信せず、Obsidianにも書き込まない。

対象一覧はC:の次のフォルダにも保存される。

```text
C:\Users\TAKUH\Documents\paperflow\.data\batches
```

## 4. 要約して保存する

対象一覧を確認し、右下の **この○本を要約して保存** を押す。

ここから一覧のPDFを外部AIへ渡す。1本ずつ本文と図表を読み、日本語要約、図表と説明、保存版PDFをObsidianへ保存する。全件を選んでも、同時に大量送信はしない。

画面には現在の論文と、要約済み・失敗・登録済みの本数が表示される。GUIでは1本の要約が完成するたびに保存する。「保存中」はPDF・図表のコピー、ノート・索引・ログの反映と変更ファイルの検証を行っている状態。次の論文の解析は、この保存が完了してから始まる。

完了すると登録済み本数と残り本数が表示される。未完了があれば「履歴・消費量」やレポートで理由を確認する。視覚読解が未完了なら、AIが回答した理由や未確認ページを表示する。認証切れ・CLI未導入など全論文に共通する障害が出ると、後続の送信を止める。原因を解消後、同じ一覧から再開する。

## 5. Obsidianで読む

**要約フォルダを開く** を押すと、保存先のフォルダが開く。ObsidianではLLM-Wikiの次の場所を開く。

```text
10_Papers
  └ 20_Source_Notes
```

論文タイトルのノートに、要点・図表と説明・結果・限界が並ぶ。ノート内のリンクから保存版PDFを開ける。

現在の保存先:

```text
H:\My Drive\LLM-Wiki\10_Papers\20_Source_Notes
```

既存Wikiへの追記は統合提案として保存する。`50_Wiki`の本文へ自動で追記はしない。

## 6. 消費量を確認する

実行中でも **レポートを開く** を押せる。「履歴・消費量」タブに現在の結果を表示し、約2秒ごとに更新する。取り込み処理はそのまま継続する。

過去の結果は「履歴・消費量」で **履歴を更新** を押し、対象の一覧を選ぶ。**結果を更新** で手動更新もできる。

登録本数、解析の試行回数、所要時間、CLIから取得できた入力・出力トークン数と費用が表示される。取得できなかった値は「不明」と表示する。費用は定額プランの残量や請求確定額ではない。

解析中の論文名、失敗理由、登録本数と取得済みの消費量を画面で確認できる。保存処理が終わる前でも閲覧できる。登録本数は保存完了をDBへ記録した分を表示する。

文章形式のレポートファイルは `.data\batches` に保存する。ファイルがまだ作成されていない段階でも、画面では現在の記録を閲覧できる。

処理中の画面を閉じずに別のPaperFlowを起動し、「履歴・消費量」で実行中の一覧を選んで閲覧することもできる。別の画面では取り込み開始を押さず、閲覧だけ行う。

## 7. 停止・再開する

処理中の **現在の論文の完了後に停止** を押す。現在の論文を保存してから停止するので、その1本の処理が終わるまで待つ。

再開するときは、そのまま **この○本を要約して保存** を押す。画面を閉じた場合は、「履歴・消費量」で該当する一覧を選び、**選んだ一覧を開く** を押す。「取り込み」の **保存済みの一覧を開く** からも選べる。

同じ一覧を再実行すると、登録済みを飛ばして残りを処理する。再開中はAI・モデル・解析設定を変更しない。失敗した論文を別の論文へ勝手に入れ替えることもない。

「変更ファイル検証に失敗しました」で停止した場合、エラーに表示されたC:の `validation-error.json` に全指摘が保存される。原因を修正して同じ一覧を再開する。AI解析が成功済みでPDF・モデル・解析設定が同じなら、保存済み回答を使って保存処理をやり直す。AI解析自体に失敗した論文は、再開時に再解析の対象になる。

## 8. 新しく追加された論文を取り込む

Paperpileへ追加し、Google Driveの同期が終わるまで待つ。

「取り込み」で **未取り込みを全件 → 対象一覧を作成** を押す。新着と、以前から残っている未処理分が選ばれ、取り込み済みは除外される。本数を絞る場合は **追加する本数** を選ぶ。

一覧を確認し、**この○本を要約して保存** を押す。以前保存した一覧には新着分は追加されないので、新しい一覧を作る。

## 9. Paperpileで削除した場合

**Obsidianへ保存済みのPDF・図表・要約は残る。自動で連動削除しない。**

| Google Drive同期後の状態 | 次の一覧作成・実行時の動作 |
|---|---|
| BibTeXから論文が消えた | 新しい対象一覧から外す |
| BibTeXには残り、原本PDFが消えた | 新しい対象一覧では選ばない |
| 保存済み一覧の未処理論文が削除された | 送信せず、未完了として報告する |
| 削除した論文を復元した | 再検出する。すでに登録済みなら除外する |

判断するのはG:へ同期されたBibTeXとPDF。同期前やBibTeXに書誌が残っている間は、書誌削除として検知しない。Obsidian側のノート・PDFを整理する削除機能はない。

## 設定・運用の詳細

### 自宅PCとラボPCで続きを引き継ぐ

**PC間同期** タブで各PCのパスと、Drive内の専用共有フォルダを設定する。最初のPCで共有を作成し、もう一方のPCで同じフォルダを選ぶ。起動後はDriveの同期完了を確認し、**確認して取り込みを許可** を押す。終了時は **共有フォルダへ保存して終了** を押し、Driveの送信完了を待ってからPCを切り替える。Google Cloud・OAuth設定は不要。モデルIDは明示して共有する。[初期設定と操作手順](multi-pc-sync.md)

### 保存先の場所や名前が変わったとき

取り込みを停止してから、**PC間同期 → このPCのパス → Obsidian Vault** を新しい場所に変更し、**このPCのパスを保存** を押す。同じVaultの保存記録を照合して履歴を引き継ぐ。PCごとに保存先のドライブ文字やフォルダ名が違っていてもよい。Vault内のフォルダ構造は維持する。

同期用共有フォルダの場所も変わった場合は、そのフォルダを選択し、Drive完了を確認して **既存の共有を引き継ぐ／場所を変更** を押す。[パス変更の手順と確認条件](multi-pc-sync.md#vaultのパスが変わったとき)

### 論文の主題タグ

要約ノートの `tags` に `topic/<主題語>` を記録する。Obsidianのタグ一覧の `topic` から内容別に探せる。従来の `topics` も保持し、内容の分類は同じ値を使う。

### AIを使わず試す

AIを **Fake（オフライン試験）** にすると、外部通信を行わずダミー要約を生成する。試す場合は合成資料とテスト用Vaultを使う。Fakeでも「Obsidianへ保存する」が有効なら、指定した保存先へ書き込む。

合成資料の作成方法とCLI操作は [CLI操作マニュアル](cli-usage.md) と [検証記録](verification.md) を参照。

### 設定ファイル

起動アイコンは `config.production.yaml` を使用する。「設定ファイルを切替」で別の設定を開くこともできる。

設定画面は値を検証して保存する。他のエディタで同時に変更された場合は上書きせず、読み込み直しを求める。全項目の説明は [config.example.yaml](../config.example.yaml) にも記載している。

### 入力上限と一時画像

現在の入力上限は300ページ、PDF64MiB、全ページ画像128MiB、補助本文300万文字。AI側のコンテキスト制限は別に適用される。[入力上限](input-limits.md)

ClaudeにはPDFを添付し、大きい場合は送信用コピーを再圧縮・画像調整してから渡す。全ページと文字・ベクトルを保持し、100ページを超える場合は省略せず分割する。画像調整時は要約にもその旨を記載する。G:原本やVaultに保存する原PDFは変更しない。agyは原PDFと同じ内容のC:の作業コピーを直接読む。Codexには全ページ画像を添付する。図表の選択と説明は本文を読む要約担当が行う。[PDFと図表の読解](visual-reading.md)

全ページ画像と作業用PDFは一時フォルダに置き、正常終了・例外・タイムアウト時に削除する。Obsidianに添付する図表は保存する。OS強制終了・停電では通常の後始末が走らない場合がある。

### 起動アイコンを作り直す

プロジェクトフォルダでPowerShellを開き、次を実行する。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\create_gui_shortcut.ps1 -Desktop
```

プロジェクトフォルダとWindowsのデスクトップにアイコンを作成する。
