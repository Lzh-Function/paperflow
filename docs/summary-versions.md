# 選択論文の再要約・版管理

## 再要約する

1. **論文一覧** で取り込み済み論文を選ぶ。複数選択はCtrl/Shiftを使う。
2. **選択論文を再要約・版を比較** を押す。
3. Providerとモデルを指定する。モデルIDの直接入力も可能。空欄はCLIの既定モデル。
4. **再要約を開始** を押し、確認画面で対象・モデル・外部送信を承認する。

選択した論文の凍結PDFを1本ずつ解析する。Claude/Codex/agyのPDF・図表読解、共通JSON検証、入力上限を通常の取り込みと共通で使う。生成した候補はC:へ保存する。現在の正式Source Note、統合提案、処理済み判定は保持する。

**この論文の完了後に停止** を押すと、現在の1本の候補を保存してから停止する。残りは未送信。次は必要な論文を選び直す。**再要約を開始** は選択分に新しい解析を行う操作なので、完成済み候補の比較には押さない。

## 比較して正式版にする

複数論文を選んだ場合は、上部の論文欄で表示対象を切り替える。履歴にはProvider・実際に取得したモデル名・生成日時・正式版/比較候補が表示される。左側は正式版、右側は選択した版。CLIが申告したトークン数・費用も表示する。取得できない値は不明となる。

**図表付きで比較を開く** を押すと、ブラウザに本文と図表を左右表示する。外部AIへの追加送信は行わない。

採用する候補を選び、**選択版を正式版にする** を押す。確認後にPaperFlow管理Source Note・統合提案・管理ハッシュ・索引・処理ログを更新する。凍結PDF、既存の図表、50_Wikiの学術本文、人間ノートは変更しない。

以前の要約も履歴に残る。旧版を選んで同じ操作をすると戻せる。本文と選択図表をセットで切り替える。切り替えはAIへ再送しない。

手動編集があるノート・提案や、Wiki統合済み出典は自動で切り替えない。引用先・根拠・人間の編集を確認するレビューが必要となる。手動登録だけでPaperFlowのreceipt・解析履歴がない出典も、この機能の対象外。

## 保存先と復旧

- 解析JSON・消費量・要約本文・図表の選択情報：C:の処理履歴DB。既存の正式版は、その論文を初めて再要約する際に履歴へ保存する。
- 比較候補の切り出し画像：`storage.data_dir/summary-versions/`。選択した図表だけを保存する。
- 比較画面：`storage.data_dir/summary-comparisons/`。同じ組み合わせの表示は更新する。
- 正式版として採用した図表：凍結出典内の `figures/pfv-<解析IDの先頭16文字>/`。旧版の画像は残す。
- 切り替え時の差分と復旧用原本：`storage.data_dir/sv/<操作ID>/`。

全ページPNGや送信用PDFは従来どおり一時領域へ置き、終了時に削除する。版として保存した本文・選択図表は履歴なので保持する。

再要約に失敗しても正式版は残る。失敗理由は版管理画面に表示する。認証等の共通障害では後続の論文を送らず停止する。

AI回答の保存後に画像作成等が失敗した場合は、**保存済み回答から候補を復元** を押す。保存済みJSONから本文・図表を作成するので、追加のAI送信はない。回答の保存を確認できない中断は、従来のPC間同期の確認手順に従う。

## PC間同期

両PCのPaperFlowをこの機能に対応した同じ版へ更新する。DBはversion 4、共有スナップショットはversion 2を使う。旧DB・旧共有データは読み込めるが、新形式を古いアプリへ戻して使うことはできない。

通常どおりDriveの同期完了を確認し、**確認して取り込みを許可** を押してから再要約・正式版切り替えを行う。再要約用のProvider/モデル指定はジョブ内で使い、通常バッチの共有解析設定は変更しない。

本文・モデル・消費量・図表の選択情報とハッシュを共有進捗へ保存する。PDFと採用済み図表はVault側のDrive同期で取得する。未採用候補の画像が別PCにない場合は、**図表付きで比較を開く** または正式版への切り替え時に、凍結PDFから選択画像だけを再現して保存時ハッシュと照合する。外部AIへ再送しない。再現結果が一致しない場合は切り替えを停止する。
