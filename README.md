# PaperFlow

Paperpileの論文をAIで読み、**図表付きの日本語要約をObsidianへ保存するWindowsアプリ**です。画面のボタンから操作できます。

論文ごとに、PDFのコピー・重要な図表・要約ノートを保存します。保存した論文は、発行年やタグで探せます。

**[操作マニュアル](docs/usage.md)** · **[初回セットアップの詳細](docs/setup.md)**

## はじめに用意するもの

- WindowsのPC。初回セットアップにはインターネット接続が必要です。
- PaperpileのPDFフォルダと、書誌情報の一覧である **BibTeXファイル（`.bib`）**。Google Drive上のファイルは、PCから開ける状態にしておきます。
- **LLM-Wiki用に設定されたObsidianの保存フォルダ（Vault）**。[対応するVaultについて](docs/llm-wiki.md)

## 1. インストールする

1. PaperFlowのフォルダを `C:\Apps\PaperFlow` など、C:内へ置きます。PaperpileやVaultとは別の場所にします。
2. フォルダ内の **`setup.cmd`** をダブルクリックします。Pythonなどの準備が終わると、PaperFlowが開きます。
3. **PC間同期 → 初期設定・保存場所の変更を表示** で、次の3つを選び、**このPCのパスを保存** を押します。1台だけで使う場合も、ここで保存場所を設定します。

| 設定する項目 | 選ぶもの |
|---|---|
| Paperpileフォルダ | 論文のPDFが入っているフォルダ |
| BibTeXファイル | 論文名・著者・発行年などが入った `.bib` ファイル |
| Obsidian Vault | LLM-WikiのVault本体のフォルダ |

4. 使うAIの **Claude Code CLI / Codex CLI / Antigravity CLI（agy）** をインストールします。導入手順は[セットアップの詳細](docs/setup.md#aiと保存先を設定する)にあります。
5. **PC間同期** タブの、対応する **Claudeにログイン / Codexにログイン / agyにログイン** ボタンでログインします。

## 2. 論文を要約して保存する

次回からは、デスクトップの **PaperFlow** アイコン、またはフォルダ内の **`PaperFlow.cmd`** をダブルクリックして起動します。

1. **取り込み** タブでAIを選び、**モデル一覧を更新** してモデルを選びます。
2. 入力元と保存先を確認します。**PDFを外部送信して解析する** と **Obsidianへ保存する** にチェックを入れ、**設定を保存** を押します。
3. 下の表から取り込む範囲を選び、**対象一覧を作成** を押します。
4. 対象の論文を確認し、**この○本を要約して保存** を押します。
5. 完了したら、**要約フォルダを開く** で保存先を確認します。使用量は **履歴・消費量** で確認できます。

| 取り込む範囲 | 動作 |
|---|---|
| **未取り込みを全件** | 取り込み可能な未保存の論文をすべて選ぶ |
| **追加する本数** | 入力した本数を、未保存の論文からランダムに選ぶ |
| **累計の目標** | 保存済みの本数を含め、入力した累計に達するまでの不足分を選ぶ |

少ない本数から試す場合は、**追加する本数** を使います。通常の取り込みでは、保存済みの論文を自動で除外します。

保存すると、ObsidianにPDFのコピーと図表付きの要約ノートが追加され、索引も更新されます。既存のWiki本文への反映は、統合案として保存します。

## 3. 保存した論文を見る

- **PaperFlowで見る：** **論文一覧** タブで、保存済み・未処理・失敗などを絞り込みます。論文を選ぶと要約が表示され、PDFや要約ノートも開けます。
- **Obsidianで探す：** `Ctrl+O` を押し、**論文データベース** と入力して開きます。発行年・著者・主題・タグで探せます。論文の追加時に自動更新されます。[詳しい使い方](docs/paper-database.md)

## 止まったとき・要約を作り直したいとき

| やりたいこと | 操作 |
|---|---|
| 途中で停止した一覧を再開する | **履歴・消費量** で前回の対象一覧を開いて再開する |
| 失敗・未保存の論文をまとめて確認する | **復旧・後処理** を開く。回答が残っているものは **再送せず復旧・保存** で検証・保存できる |
| 別モデルでも要約を作る | **論文一覧 → 選択論文を再要約・版を比較** から対象とモデルを選ぶ。候補を比較して正式な要約を選べる |
| ログイン切れなどの原因を調べる | **履歴・消費量** のレポートと[トラブル対応](docs/troubleshooting.md)を確認する |

操作の詳細は[操作マニュアル](docs/usage.md)、要約の比較は[版管理の説明](docs/summary-versions.md)を参照してください。

## 自宅とラボのPCで使う

両PCに同じ版のPaperFlowを入れ、**PC間同期** タブで同じ専用共有フォルダを設定します。PaperpileやVaultのパスは、PCごとに違っていても構いません。

PCを切り替えるときは、前PCで **共有フォルダへ保存して終了** を押し、両PCのGoogle Driveの同期完了を確認します。次のPCでは **確認して取り込みを許可** を押してから続けます。

保存先の場所や名前が変わった場合も、**PC間同期** から新しいパスを設定します。[PC間同期・パス変更の手順](docs/multi-pc-sync.md)

## 設定とデータについて

- 設定は通常、画面の **設定** タブから変更します。設定ファイルは `config.production.yaml` です。直接編集する場合は、各項目の日本語コメントを参照してください。[設定の見本](config.example.yaml)
- AI解析では、選んだCLIを通じて論文の本文・図表を外部のAIへ送信します。対象と送信先を確認して実行してください。
- Paperpileの原PDF、既存の学術本文・人間のノート、Obsidianのアプリ設定は保持します。Paperpileで削除した論文も、Obsidian側の保存済みノートは残ります。

## 更新・開発用の情報

更新するときはPaperFlowを閉じ、Gitでソースを更新してから **`setup.cmd`** を再実行します。既存の設定・処理履歴・保存済み要約は引き継ぎます。

開発用のセットアップとテストは、プロジェクトフォルダのPowerShellで実行します。

```powershell
.\setup.cmd -Dev -NoLaunch
.\.venv-win\Scripts\python.exe -B -X utf8 -m pytest -q
```

- [コマンドで操作する](docs/cli-usage.md)
- [PDF・図表の読み取りと入力上限](docs/visual-reading.md)
- [設計仕様](docs/DESIGN.md)・[検証記録](docs/verification.md)・[依存ライブラリのライセンス](docs/licenses.md)

個人設定・`.data/`・実PDF・認証情報はGitの対象外です。別PCへの進捗の引き継ぎには、アプリの **PC間同期** を使います。
